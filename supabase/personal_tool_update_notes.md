# 本人の個人工具修正

適用順序：既存 `personal_tool_registration.sql` および登録詳細の更新が適用されたDBに、`add_personal_tool_update.sql` を実行してからUIを公開する。続けて `add_personal_tool_identity_correction.sql` を適用する（適用済みの通常修正RPCも更新する）。今回の作業では実DBへの適用は行っていない。

## DB側の制限

`update_personal_tool` は認証済みユーザーのみ実行可能。社員IDは引数として受け取らず、`auth.uid()` と有効社員レコードから求める。UPDATEのWHERE句に工具ID・personal所有区分・本人社員IDを指定する。管理者として呼び出しても、このRPCでは他人の工具を変更できない。

更新列は大分類、工具名、規格、メーカー、型式、製造番号、性能、点検区分、備考に限定する。点検要否は大分類から、更新日時はDB時刻から自動設定する。管理番号、所有者、所有区分、状態、現場、貸出管理設定、その他内部列はSET句に含めない。通常修正は大分類・工具名の変更も拒否し、再採番しない。専用の訂正RPCのみ、履歴なし・未運用を確認して管理番号を再採番する。

工具名は既存の `personal_tool_catalog()` で大分類との組み合わせを検証する。充電工具は点検不要・区分NULL、その他は既存5区分の選択を必須にする。

既存RLS・テーブル権限・管理者RPCは変更しない。リポジトリに既存tools UPDATE/ALLポリシー一式がないため、実DBの直接UPDATE経路については未確認。`personal_tool_update_verify.sql` の結果で、一般社員に任意の工具列を直接更新できるポリシーや別RPCがないことを確認する必要がある。専用RPCの制限は、別経路に既に存在する権限を取り消すものではない。

## 大分類・工具名の登録間違い訂正

- 通常修正では大分類・工具名を固定する。「工具名を訂正する」で工具名の選択を有効にし、専用の correct_personal_tool_identity RPCを呼ぶ。修正画面では大分類の入力欄は非表示。選択した工具名に対応する大分類を既存マスタから内部設定する。複数分類にある別の工具名は分類を推測せず保存を拒否し、管理者への確認を案内する。訂正をやめると元の大分類・工具名・点検区分へ戻る。
- DBが変更前の工具をロックして所有者を再確認する。大分類または工具名の変更時は常に既存 allocate_tool_management_code を使用する。旋盤への訂正では1IN〜4INの選択が必要。ID、所有者、所有区分は不変。管理番号の入力引数はない。既存UNIQUE制約と採番advisory lockは維持。
- 必須履歴は tool_inspections（点検）、tool_history（貸出・返却・移動）、tool_battery_history（交換）。一件でもあれば拒否。必須テーブル・参照列がなければ安全側に拒否。
- その他、publicの tool_id／末尾 _tool_id、management_code／末尾 _management_code 列、全スキーマの tools への外部キー列を実DBカタログから検出し、参照レコードがあれば拒否。toolsのid・management_code以外への外部キーは未対応として拒否。
- 参照テーブルを一定順序でSHAREロックしてから対象工具をFOR UPDATEし、ロック待ち後の履歴を再確認する。履歴INSERT/UPDATE/DELETEは訂正のコミットまで待機する。一般の登録・点検処理は変更しないが、訂正中は履歴書込みが一時的に待機する場合がある。古いスナップショットでの判定を防ぐためREAD COMMITTEDのみ許可。
- 現場設定済み、available以外の状態、無効工具も訂正不可とする。貸出状態変更と履歴追加が別HTTPリクエストで行われる既存構成を考慮する。
- 既存QRはtool.idで詳細画面を開き、読み取り・印刷だけの永続履歴はリポジトリ上にない。tool.idを維持するため既存URLは継続利用可能。ただし印字済み管理番号のラベルは差し替える。
- JSON内だけの参照、外部システムのログ、外部キーも規約に沿う列名もない独自履歴は自動検出できない。実DBの履歴構成は未確認のため、公開前にこれらがないことを確認し、存在する場合は判定へ追加する。専用RPC以外の既存UPDATE権限も確認が必要。

DB回帰テストは tests/personal-tool-identity-db.test.sql。空の専用PostgreSQLテストDBに対して psql -X -v ON_ERROR_STOP=1 -f tests/personal-tool-identity-db.test.sql を実行する。本番DBでは実行しない。この環境ではPostgreSQL実行環境がなく未実行。

## 修正画面の文言

- 見出し：個人工具を修正
- 管理番号：BI-001 のように表示のみ。「変更不可」の補足は付けない。
- ボタン：工具名を訂正する
- 説明：工具名を訂正すると、管理番号もその工具用に自動変更されます。
- 運用記録がある場合：この工具はすでに点検や使用の記録があるため、工具名を訂正できません。管理者に連絡してください。
- 通常修正できるのは規格・メーカー・型式・製造番号・性能・点検区分・備考。通常修正RPCは管理番号を変更しない。

今回の文言変更を既存DBへ反映する場合は、更新済み add_personal_tool_identity_correction.sql を再適用する。引数、本人所有制限、採番、記録判定、既存RLSは変更していない。旧RPCの記録ありエラーも画面側で指定文言に変換する。
